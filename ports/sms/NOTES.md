# Master System / Game Gear / SG-1000 port: notes

Unattended work, 2026-09-29. No board attached, so nothing here has run on a Fruit Jam.

## Core choice

- **Wrote the core.** Checked, not assumed: SMS Plus / SMS Plus GX (libretro/smsplus-gx
  README) is GPLv2 or later, and the Pico/ESP32 forks are GPL-2.0/3.0. Genesis Plus GX's
  LICENSE.txt forbids commercial use and requires source for modified redistributions, so not
  permissive either. A permissive Z80 exists (superzazu/z80, MIT per GitHub), but it steps one
  instruction per call through memory/port callbacks, which is slow here, and the VDP, PSG and
  mappers would still have to be written. So `src/smscore.h` is new MIT code for this repo: a switch-dispatched Z80
  (opcode cases generated by `src/gen_z80.py` into `src/z80_ops.inc`), scanline VDP, PSG,
  mappers. No third-party code. The TMS9918 RGB values are the commonly published ones.
- **One module for three systems.** `sms.init(st, rom, system)`; `code.py` picks the system
  from the extension (`.sms`, `.gg`, `.sg`), first match in sorted order on `/sd`, then `/`.

## Decisions made without asking

- **Z80 register model.** A, F, BC, DE, HL, SP, PC and WZ (MEMPTR) are locals inside
  `z80_run()`; IX/IY, the shadow set, I, R live in the state struct. Flags are computed
  eagerly with 256-entry SZ/SZP tables built at init. X/Y undocumented flags and MEMPTR are
  implemented, which is why zexall passes too. SCF/CCF take X/Y from A (the classic NMOS
  model, what zexall expects).
- **Interrupts.** Checked before every instruction (NMI edge, IRQ level from the VDP). EI
  delays acceptance by one instruction. IM 0 and IM 1 both go to $38 (the SMS data bus reads
  $FF), IM 2 reads the vector at I:$FF. HALT skips straight to the end of the time slice when
  nothing can interrupt it.
- **Scanline VDP.** Each visible line is drawn at the start of the line from current
  registers, then the CPU runs 228 T-states. Line counter decrements on lines 0..height
  (inclusive) and reloads below that; the frame flag is set on line height+1 (193 for 192-line
  mode), following Charles MacDonald's VDP notes. Vertical scroll is latched once per frame.
  H counter is computed from the cycle within the line (not latched by TH).
- **Mode 4** has the H scroll lock for the top 2 rows, V scroll lock for the right 8 columns,
  left column blank, sprite shift, 8x16 and zoomed sprites, 8 sprites per line with the
  overflow flag, sprite collision, BG priority, and the SMS2 224/240-line modes (SMS only; Game
  Gear stays 192). The SMS1 name table address mask quirk is not emulated (SMS2 behaviour).
- **TMS9918 modes** (SG-1000, and SMS games that use them): Graphics I, Graphics II (with the
  register address masks), Multicolor, Text; 32 sprites, 4 per line with 5th-sprite flag and
  number, 8x8/16x16, magnification, early clock, collision.
- **Game Gear display: 2x horizontal, 1.5x vertical** (320x216, centered, 12 px bars top and
  bottom). 2x vertical would be 288 lines, more than the 240-line buffer. 1.5x is done by
  drawing even source lines twice and odd lines once, so pixel rows alternate 2 and 1 lines
  tall; that can shimmer slightly on vertical scrolling. The GG LCD's pixels are wider than
  tall, so 2:1.5 is close to the real shape. The choice is automatic from the framebuffer size
  (`ctx_layout()` in `sms.c`): 2x vertical if the buffer has 288 lines, 1x if under 216.
- **SMS and SG-1000 display: 1:1 centered**, 256x192 at (32, 24). SMS2 tall modes re-center
  and clear the buffer when the height changes.
- **Colors.** SMS CRAM 6-bit and GG CRAM 12-bit are converted to RGB565 on write, and the
  frontend builds RGB565/RGB332 lookup tables when any entry changes.
- **Audio.** SN76489: 3 tones + noise (16-bit LFSR, taps 0 and 3, the SMS/GG variant, also used
  for SG-1000 whose chip has a 15-bit register; the noise timbre differs slightly there).
  Mono at 22050 Hz, 368 samples per frame = 59.92 fps, the NTSC frame rate exactly. Point
  sampled (no band limiting), tone period 0/1 held high so volume-write sample playback works,
  DC removed with a slow tracker. The PSG is caught up on every write so mid-frame changes
  land at the right sample. GG stereo (port 6) is ignored. No YM2413 FM.
- **Mappers.** Sega (FFFC-FFFF, first 1 KB fixed, 32 KB cart RAM in two banks), Codemasters
  (detected from the checksum pair at $7FE6/$7FE8, writes to $0000/$4000/$8000, the 8 KB RAM at
  $A000 when bit 7 of the $4000 write is set), and plain ROM for SG-1000 (up to 48 KB, 8 KB RAM
  mirrored at $C000-$FFFF). Plain 32/48 KB SMS carts work through the Sega mapper's power-on
  banks (0, 1, 2). A 512-byte copier header is skipped. No Korean / 4 Pak / MSX mappers.
- **Cart RAM** is only present when the caller passes a buffer (`set_cart_ram`); `code.py`
  always does for SMS/GG and writes `<rom>.sav` only once the game has enabled cart RAM
  (`cart_ram_used`) and the contents changed, every 30 s and on exit. This keeps the hot state
  buffer at 30 KB.
- **I/O.** Export (overseas) console: the nationality check through port $3F/$DD sees the TH
  levels it drives. Reset button never pressed. Port $3E (memory control) ignored, no BIOS.
  Game Gear port 0 reports export + NTSC, Start on bit 7.
- **Controls.** Same chords as the NES port plus one: BUTTON2+BUTTON3 is button 2. The pause
  button raises an NMI on SMS and SG-1000 on press; on Game Gear it is Start. USB pad: B/Y =
  button 1, A/X = button 2 (left and right face buttons, like the SMS pad), Start = Pause.
- **Screenshot.** `SCREENSHOT_AT = 0` near the top of `code.py`. When set, after that many
  frames it prints `BEGIN_FB 320 240 <bpp>`, base64 lines of 76 characters (converted 1140
  bytes at a time), `END_FB`, then keeps running. `tools/fb2png.py` turns a serial capture into
  a PNG. The host harness writes the same format.

## Verified (host, `src/run_tests.sh`, all pass)

- **zexdoc: all 67 groups OK. zexall: all 67 groups OK** (undocumented flags included). Run in
  a CP/M stub (`host_sms zex`): BDOS calls 2 and 9 via an OUT trap at $FE00, exit via $0000.
  About 9.5 s each on an Apple Silicon Mac, 46.7 G T-states.
- PSG pitch: tone period 254 measures 439.4 Hz from zero crossings (440.4 expected).
- Sega mapper (bank registers, fixed first 1 KB, registers mirrored to RAM, cart RAM banks) and
  Codemasters mapper (slots, $A000 RAM) on a synthetic 256 KB ROM.
- Frame CRCs pinned after checking each screenshot by eye (all looked right: correct text,
  colors, sprites, no garbage):
  - SMS: SwordWork title and in game (sprites, items, enemies); Astro Climber in game (64 KB,
    Sega mapper paging, left column blank, vertical scroller with a status panel); Nyan Cat SMS
    build (TMS mode on the SMS VDP).
  - Game Gear: SwordWork Micro title and in game (window crop, 12-bit color, 1.5x layout);
    Tetris4GG in game (128 KB, Start button on port 0).
  - SG-1000: SwordWork title and in game (Graphics II, 16x16 sprites); Nyan Cat; Structris in
    game.
- Also looked at by eye, not pinned: Get Blue Spheres (256 KB), Mazy2 Micro (GG), Cross Snake
  (SG), the SN76489 test ROM UI, Skyroads FMV (4 MB). All displayed correctly as far as the
  title screens go.
- `code.py` passes `python3 -m py_compile`, and ran end to end under CPython with stub
  `board`/`picodvi`/`keypad` modules and a ctypes build of `sms.c` standing in for the `.mpy`:
  found the ROM on the fake `/sd`, picked Game Gear, ran 620 frames, printed a screenshot
  block that `tools/fb2png.py` decoded to the expected picture.
- `.mpy` builds clean with `-Werror`, no undefined symbols beyond the dynruntime ones, no
  writable static data (bss 0), 77 KB.

## Not verified

- Nothing has run on a Fruit Jam. The natmod glue (`sms.c` bottom half) follows the NES
  module closely but has not been loaded by CircuitPython.
- Audio was checked for pitch and levels only, not listened to.
- No commercial games tested (none available). Games relying on mid-line effects, exact
  interrupt timing, the SMS1 VDP quirks, or H counter latching may glitch.
- Codemasters only tested with the synthetic ROM (no free Codemasters-mapped homebrew found).
- SMS2 224/240-line modes: code is there, no test ROM used them.
- The PauseTest homebrew (FluBBa) waits in its NMI handler for a second NMI; it runs, but the
  result screen was not interpreted.

## Speed estimate

No board, so instruction counts come from `src/armbench/` (reused from the NES port): the same
C built for Cortex-M4 with the same flags as the `.mpy` (-O2 -funroll-loops), run under
Unicorn, counting Thumb-2 instructions on every 10th frame. Calibration from the NES notes:
the parent project's Peanut-GB measures 1.49 M instructions/frame on this bench and runs at
62.6 fps on the board, so 1.61 cycles per instruction.

| workload (RGB565 output, audio on) | mean instr/frame | worst | est. fps (mean / worst) |
|---|---|---|---|
| SwordWork SMS, title then in game | 1.00 M | 1.13 M | 93 / 82 |
| Astro Climber SMS, in game | 0.96 M | 1.13 M | 97 / 82 |
| SwordWork SG-1000 | 1.01 M | 1.08 M | 92 / 87 |
| SwordWork Micro GG (320x216 out) | 0.93 M | 1.02 M | 100 / 92 |
| Tetris4GG | 0.84 M | 0.88 M | 110 / 105 |

Split (SMS): VDP render ~50%, Z80 ~26%, framebuffer write ~17%, PSG ~4%. Full speed is 59.92
fps, so there is ~35% margin even on the worst sampled frame. The parent port's live play ran
~20% below its bench; if that repeats, still ~65 fps worst case. Host: ~350 us/frame (with
CRC on).

To reproduce: `pip install unicorn capstone pyelftools`, then in `src/armbench`,
`./build.sh && python3 bench.py sms ../testroms/SwordWork-SMS/sword.sms 1200 "300-306:10,420-900:08"`.
