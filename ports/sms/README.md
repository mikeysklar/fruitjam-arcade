# CircuitPython Master System / Game Gear / SG-1000

Sega 8-bit games on an Adafruit Fruit Jam, running under stock CircuitPython. The emulator is a
small core written for this project (MIT), compiled into a native `.mpy` module like the Game
Boy port in the parent directory. One module, `sms`, runs all three systems.

Not yet tested on hardware. See [NOTES.md](NOTES.md) for what has been verified.

## What you need

| part | notes |
|---|---|
| Adafruit Fruit Jam | RP2350 |
| CircuitPython 11.0.0-alpha | the `.mpy` is built for this version |
| HDMI monitor | 320x240 buffer, doubled to 640x480 by the HDMI output |
| headphones or speaker | optional |
| USB gamepad | optional, the 3 onboard buttons work too |
| a ROM | `.sms`, `.gg` or `.sg`, not included |

## Setup

Back up your `CIRCUITPY` drive first. `code.py` will be replaced.

```sh
git clone https://github.com/mikeysklar/fruitjam-arcade
cp -r fruitjam-arcade/ports/sms/CIRCUITPY/* /Volumes/CIRCUITPY/
cp MyGame.sms /Volumes/CIRCUITPY/
```

Optional, for sound and gamepad:

```sh
circup install adafruit_fruitjam relic_usb_host_gamepad
```

The board resets and the game boots.

- The first `.sms`, `.gg` or `.sg` file found on the SD card (`/sd`), then on `CIRCUITPY`, is
  loaded. The extension picks the system.
- Battery saves go to `MyGame.sav` next to the ROM, every 30 s when changed and on exit.
  Saving to `CIRCUITPY` needs it writable from code (a `boot.py` remount), `/sd` just works.
- Serial console prints fps every 5 seconds.
- Free homebrew to try: SwordWork by inufuto has an SMS, a Game Gear and an SG-1000 version
  ([SMS Power](https://www.smspower.org/Homebrew/SwordWork-SMS)).

## Systems

| system | extension | picture on the 320x240 buffer |
|---|---|---|
| Master System | `.sms` | 256x192 at 1x, centered (224/240-line modes too) |
| Game Gear | `.gg` | 160x144 scaled 2x wide, 1.5x tall = 320x216, centered |
| SG-1000 | `.sg` | 256x192 at 1x, centered |

Cartridge types: Sega mapper (most games, with battery RAM), Codemasters, and plain ROMs up to
48 KB. NTSC only. No FM sound (YM2413), no light gun, no second controller.

| Button 2 | Right | Right |
| Button 3 | Button 1 | Button 1 |
| Button 1 + 2 | Pause | Start |
| Button 1 + 3 | Down | Down |

## Speed

Estimated, not measured on the board yet. Instruction counts come from running the Cortex-M
build under Unicorn, scaled by the cycles per instruction the Game Boy port shows on real
hardware (see NOTES.md).

```
Sega 8-bit core on a Fruit Jam @ 150 MHz (estimate)
+-----------------------------------+-------------+--------+
| test                              | instr/frame | fps    |
+-----------------------------------+-------------+--------+
| Peanut-GB Tetris (measured 62.6)  | 1.49 M      | 62.6   |
| SMS SwordWork, mean               | 1.00 M      | ~93    |
| SMS Astro Climber, worst frame    | 1.13 M      | ~82    |
| Game Gear SwordWork Micro, mean   | 0.93 M      | ~100   |
| SG-1000 SwordWork, mean           | 1.01 M      | ~92    |
+-----------------------------------+-------------+--------+
Full speed is 59.92 fps.
```

## Build the `.mpy` yourself

Same toolchain as the parent project:

```sh
cd fruitjam-arcade/ports/sms/src
make MPY_DIR=../../../../circuitpython ARCH=armv7emsp
cp sms.mpy ../CIRCUITPY/lib/
```

Host tests (any C compiler, downloads the Z80 exercisers and free homebrew):

```sh
cd fruitjam-arcade/ports/sms/src
./get_testroms.sh
./run_tests.sh
```

Screenshots: set `SCREENSHOT_AT` in `code.py` to a frame number, capture the serial output to a
file, then `python3 tools/fb2png.py capture.txt shot.png`.

## How it works

- `src/smscore.h` is the emulator: Z80 CPU, VDP, SN76489 sound, mappers. The Z80 opcode switch
  (`src/z80_ops.inc`) is generated by `src/gen_z80.py`. `src/sms.c` wraps it as a CircuitPython
  native module.
- The Z80 passes zexdoc and zexall, including the undocumented flags.
- The VDP draws each scanline in one go, then the CPU runs through that line. Line interrupts,
  scroll locks, sprite limits and collisions work per line.
- The emulator draws each line straight into a `picodvi.Framebuffer`. No displayio refresh.
- Sound (3 tone channels + noise) goes into a looping `audiocore.RawSample` on the Fruit Jam's
  TLV320 DAC.
- All buffers are Python-owned. The native code allocates nothing.

## Known issues

- Register changes in the middle of a scanline show up one line late. Effects that rely on
  exact cycle timing within a line may glitch.
- Game Gear's 1.5x vertical scale draws alternate source lines twice, so vertical scrolling
  can shimmer a little.
- The Master System 1 VDP quirks are not emulated (it behaves like an SMS2).
- Game Gear stereo sound is mixed to mono. No FM sound unit.
