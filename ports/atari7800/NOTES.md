# Atari 7800 port notes

Unattended port, 2026-09-29. Nothing here has run on a Fruit Jam yet.

## Core choice

ProSystem, a7800, js7800 and Wii7800 are GPL. MAME's 7800 driver (`src/mame/atari/maria.cpp`,
`a7800.cpp`, `src/devices/bus/a7800/`) is BSD-3-Clause, so it was used as the reference for
behavior. The code is new and MIT:

- `src/cpu6502.h`: copied unchanged from `../atari2600/src` (same repo, MIT). NMOS 6502 with
  the undocumented opcodes. NMI (DLI) is done in the run loop in `atari7800.c`.
- `src/atari7800.c`: MARIA, TIA sound, RIOT, POKEY, cart mappers, module glue.
- `src/palette.h`: MAME's NTSC palette values (BSD-3-Clause, `src/LICENSE.mame`), generated by
  `src/gen_palette.py` from `a7800.cpp`.

## Decisions made without asking

- **No BIOS.** The BIOS is copyrighted and not needed: the CPU starts at the cart reset vector
  with S=$FF, I=1, MARIA DMA off, RAM zeroed, 7800 mode locked. The cart signature is not
  checked. Games that rely on BIOS leftovers could misbehave (none of the test carts do).
- **MARIA model follows MAME.** Line RAM holds 160 five bit cells (palette + color bits);
  write mode (160A/320A/320D vs 160B/320B/320C) decides how a byte becomes cells, read mode
  (CTRL bits 0-1) decides how cells become pixels when the line is shown. DMA starts 28 MARIA
  clocks into the line: 16 startup, 8 per 4 byte header, 10 per 5 byte header, 3 per direct
  byte, 6 (9 for two byte chars) per indirect byte, +6 on the last line of a zone and +17
  more if the next zone has a DLI; the CPU is held for ceil(clocks / 4) cycles, or to the end
  of the line if DMA runs past 426 clocks. Holey DMA skips the byte (no cycles, no cell move).
- **One line of latency**, as on hardware: DMA on line L builds the line shown on line L+1,
  and the pixels are made at DMA time of L+1 with the palette registers of that moment.
  Mid-line palette or CTRL changes therefore apply to the whole line.
- **Zones:** the DLL is read from DPPH/DPPL on line 16 only; the first zone gets one extra
  line (MAME does the same). DLI NMI fires right after the DMA that fetched the entry.
- **MSTAT** bit 7 is set outside lines 16..257 (NTSC). **WSYNC** holds the CPU to the end of
  the line the write landed in.
- **Slow accesses:** TIA ($00-$1F and mirrors) and RIOT I/O ($280-$2FF, $380-$3FF) cost 6
  MARIA clocks (1.19 MHz), everything else 4. The extra time is added after the instruction.
- **Display window:** framebuffer row 0 is scanline 17, 240 rows (MARIA shows lines 17-257).
  `code.py` adds 25 for PAL carts. 160 modes are drawn 2x wide, 320 modes 1:1.
- **Memory map:** RAM $1800-$27FF with $2040-$20FF and $2140-$21FF mirrored at $0040 and
  $0140 (no $2800+ mirrors, following MAME's note). RIOT RAM at $0480 (mirror $0580).
  Unmapped reads return $FF, undefined MARIA reads $00.
- **Cart types** come from the `.a78` header bits the way MAME decodes them. Headerless
  `.bin`: up to 48K flat, 144K SG9, anything else SuperGame. Plain SuperGame maps the second to
  last bank at $4000 (MAME's choice). VersaBoard is treated as SuperGame + 16K RAM (no RAM
  banking). Activision, Absolute, banksets and other special mappers return error 2.
- **Input:** SWCHA high nibble is joystick 1. INPT1 is the left button (INPUT_FIRE1), INPT0
  the right button (INPUT_FIRE2), both read $80 when pressed. INPT4 reads pressed if either
  button is down and SWCHB bit 2 is not driven low (one button mode), as in MAME. RIOT port B
  DDR starts at 0, which keeps INPT4 working for games that expect it. Pause is SWCHB bit 3.
- **Onboard buttons:** B1 left, B2 right, B3 fire, B1+B2 reset, B2+B3 up, B1+B3 down, all
  three pause (the 2600 port uses all three for select; pause is more useful on the 7800).
  Gamepad Start is Reset because most 7800 games start with Reset or fire.
- **TIA sound:** the channel model from `../atari2600`, clocked twice per scanline
  (31.54 kHz, 0.4% above the real 31.40 kHz since a 7800 line is 227 color clocks, not 228).
- **POKEY:** written from the documented register behavior. Four channels, 64 kHz / 15 kHz /
  1.79 MHz clocks, 16 bit joined pairs, high-pass bits, 4/5/9 bit polynomials by table on the
  CPU cycle count, the 17 bit polynomial stepped once per channel pulse (sounds like noise,
  not bit exact). Output high time is integrated over each audio tick. RANDOM reads $FF while
  SKCTL holds POKEY in reset (7800basic uses that to detect a POKEY). Silent channels only
  keep their divider phase. No serial port, pots, keyboard or POKEY IRQs.
- **Mix:** TIA alone 0..30000; with a POKEY cart TIA and POKEY are each scaled so the sum of
  all six channels at full volume is ~30000. Mono, 22050 Hz, paced by samples made (like
  `../atari2600`).

## Test cartridges

- **Own test cart** `src/testcart/make_testcart.py` (a tiny assembler in Python, all our code)
  builds `testcart.a78` plus a list of expected pixels worked out by hand: 160A with a
  transparent overlap, 160B, 320A, 320B, 320C, 320D, indirect mode with one and two byte chars,
  holey DMA 8 and 16, kangaroo mode, a background color change from a DLI, SWCHA and INPT1
  through a palette register, and a TIA tone (AUDC 4, AUDF 15).
- **7800basic samples.** 7800basic (github.com/7800-devtools/7800basic) is GPL-2 for the
  compiler, but its 6502 runtime and generated code are CC0 and its license says programs you
  build are yours. `src/get_testroms.sh` downloads the v0.41 WebAssembly release and wasmtime
  v49.0.1 and builds the samples into `src/testroms/` (gitignored). Two samples (backuptest,
  languagetest) build broken from the release and are skipped; banksets needs the banksets
  mapper, which is not supported.
- **Recommended test ROM for the board: `eightysix.a78`** (SuperGame + RAM, POKEY at $450, a
  160A title banner, 86 moving sprites, POKEY music). For a playable one with TIA sound:
  `smasteroids.a78` (48K; fire to start). Both are in `src/testroms/` after
  `./get_testroms.sh`. Copy one to the SD card or CIRCUITPY root. `SCREENSHOT_AT = 600` in
  `code.py` gives the same frame as the pinned host CRC.

## Verified (host only, `src/run_tests.sh`, all pass)

- Klaus Dormann's 6502_functional_test reaches the success trap at $3469 (30,646,176
  instructions). The atari2600 port's own CPU checks (undocumented opcodes, cycle counts) pass.
- Test cart: 138 pixel checks pass and the tone measures 985.4 Hz (expected 985.6).
- 35 of the 36 built 7800basic samples boot (banksets is refused, error 2) and show a sensible screen (checked by eye in
  screenshots): text in 320A, 160A games, 320C sprites, DLI mode splits, 101 and 86 sprite
  demos, SuperGame + RAM double buffering, POKEY detection ("POKEY STATUS... FOUND").
  Frame CRCs are pinned for 13 of them, some with joystick/fire input scripts (sprite moves,
  Smasteroids game in progress with a score).
- POKEY tones in the Daisy Bell sample measured with a Goertzel filter at the expected
  frequencies (779, 262, 165, 131 Hz for AUDF 40/121/193/243 at 64 kHz). TIA music in
  trackertest plays.
- The screenshot path: `code.py`'s `screenshot()` run under CPython on a host framebuffer
  gives a capture that `tools/fb2png.py` turns into a PNG identical to the host dump's.
- `.mpy` builds clean (49.9 KB, bss 0, no undefined symbols beyond dynruntime).
  `STATE_SIZE` is 24,624 bytes on ARM. `code.py` passes `python3 -m py_compile`.

## Not verified

- Nothing has run on a Fruit Jam. Python API, framebuffer output, audio ring and input follow
  the atari2600 port but are untested on hardware.
- No commercial 7800 game and no BIOS were tested. No reference emulator was available on
  this machine, so correctness beyond the hand-checked test cart is "looks right".
- 160B, 320B and 320D are only covered by the test cart (no sample uses them), and their
  expected pixels come from the same reading of MAME that the code follows.
- DMA cycle stealing is only checked indirectly (games run at the right pace, pinned CRCs).
- Audio was checked for levels and pitch, not listened to.

## Speed estimate

No board, so instruction counts come from `src/armbench/`: the same C built for Cortex-M4
with the `.mpy` flags, run under Unicorn, counting Thumb-2 instructions on every 10th frame.
Calibration is the nes/ port's: Peanut-GB Tetris is 1.49 M instructions/frame on this bench and
runs at 62.6 fps on the board, so 1.61 cycles per instruction at 150 MHz.

| workload (900 frames) | instr/frame | est. cycles | est. fps |
|---|---|---|---|
| smasteroids, playing | 0.94 M | 1.51 M | 99 |
| onehundredandone, 101 sprites | 1.09 M | 1.75 M | 86 |
| eightysix, 86 sprites + banner + POKEY | 1.32 M | 2.13 M | 70 |

Split for eightysix: DMA (line RAM build) ~45%, pixel output ~19%, CPU ~18%, POKEY ~8%.
The nes/ port ran ~20% below its bench estimate on the board at first; if that repeats the
heaviest carts land near 56-60 fps. ROM and state may sit in PSRAM; MARIA reads the ROM for
every graphics byte, so PSRAM latency is the main unknown.

To reproduce: `pip install unicorn capstone pyelftools`, then in `src/armbench`,
`./build.sh && python3 bench.py a78 ../testroms/eightysix.a78 900`.
