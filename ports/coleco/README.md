# CircuitPython ColecoVision

ColecoVision games on an Adafruit Fruit Jam, running under stock CircuitPython. The emulator
(Z80, TMS9918A video, SN76489 sound) is written for this project (MIT) and compiled into a
native `.mpy` module like the Game Boy port in the parent directory.

Not yet tested on hardware. See [NOTES.md](NOTES.md) for what has been verified.

## What you need

| part | notes |
|---|---|
| Adafruit Fruit Jam | RP2350 |
| CircuitPython 11.0.0-alpha | the `.mpy` is built for this version |
| HDMI monitor | 256x192 picture in a 320x240 frame, doubled to 640x480 |
| headphones or speaker | optional |
| USB gamepad | optional, the 3 onboard buttons work too |
| a `.col` cartridge image | not included |
| `coleco.rom` BIOS | optional, only needed for commercial games (see below) |

## Setup

Back up your `CIRCUITPY` drive first. `code.py` will be replaced.

```sh
git clone https://github.com/mikeysklar/fruitjam-arcade
cp -r fruitjam-arcade/ports/coleco/CIRCUITPY/* /Volumes/CIRCUITPY/
cp MyGame.col /Volumes/CIRCUITPY/
```

Optional, for sound and gamepad:

```sh
circup install adafruit_fruitjam relic_usb_host_gamepad
```

The board resets and the game boots.

- The first `.col` file on the SD card (`/sd`), then on `CIRCUITPY`, is loaded.
- Serial console prints fps every 5 seconds.

## BIOS

A real ColecoVision needs its 8 KB BIOS ROM, which is copyrighted and not included.

- **Without it** a small open BIOS built into `coleco.mpy` is used. It boots any cartridge
  that drives the hardware itself: most homebrew, including everything made with
  [CVBasic](https://github.com/nanochess/CVBasic). There is no Coleco title screen.
- **Commercial games** call the BIOS for sound, controllers and graphics. For those, copy a
  dump of your own console's BIOS next to the cartridge as `coleco.rom` (8192 bytes). It is
  picked up automatically.

## Controls

The ColecoVision controller has a joystick, two fire buttons and a 12-key keypad. Games use
the keypad to pick skill level (1-4) and often `*` or `#` to restart or pause.

| USB gamepad | ColecoVision |
|---|---|
| D-pad or stick | Joystick |
| A | Left fire |
| B | Right fire |
| Start | Keypad 1 |
| Select | Keypad 2 |
| X | Keypad * |
| Y | Keypad # |
| Select + Start | Keypad 3 |
| Select + A / B / Y | Keypad 4 / 5 / 6 |
| Select + Up / Right / Down | Keypad 7 / 8 / 9 |
| Select + X or Left | Keypad 0 |

| Fruit Jam | ColecoVision |
|---|---|
| Button 1 | Left |
| Button 2 | Right |
| Button 3 | Left fire |
| Button 1 + 2 | Keypad 1 |
| Button 1 + 3 | Keypad 2 |
| Button 2 + 3 | Right fire |

All of this is in the `CONTROLS` section at the top of `code.py`; edit the tables to remap.

## Speed

Estimated, not measured on the board yet. Instruction counts come from running the Cortex-M
build under Unicorn, scaled by the cycles per instruction the Game Boy port shows on real
hardware (see NOTES.md).

```
ColecoVision core on a Fruit Jam @ 150 MHz (estimate)
+------------------------------------+-------------+--------+
| test                               | instr/frame | fps    |
+------------------------------------+-------------+--------+
| Peanut-GB Tetris (measured 62.6)   | 1.49 M      | 62.6   |
| Space Attack, playing, mean        | 0.71 M      | ~130   |
| oscar (Z80 busy all frame), mean   | 1.02 M      | ~91    |
| worst sampled frame (any cart)     | 1.08 M      | ~86    |
+------------------------------------+-------------+--------+
ColecoVision needs 59.9 fps for full speed.
```

## Build the `.mpy` yourself

Same toolchain as the parent project:

```sh
cd fruitjam-arcade/ports/coleco/src
make MPY_DIR=../../../../circuitpython ARCH=armv7emsp
cp coleco.mpy ../CIRCUITPY/lib/
```

Host tests (any C compiler; downloads the Z80 exercisers and builds free CVBasic demo carts):

```sh
cd fruitjam-arcade/ports/coleco/src
./get_testroms.sh
./run_tests.sh
```

## How it works

- `src/z80.h` is the CPU, `src/cv.h` the rest of the machine (memory map, VDP, PSG,
  controllers, MegaCart banking). `src/coleco.c` wraps it as a CircuitPython native module.
- The Z80 opcode switches are generated by `src/gen_ops.py`. It passes zexdoc and zexall.
- The VDP draws each scanline in one go, then the CPU runs through that line (228 cycles).
  Graphics I, Graphics II, Multicolor and Text modes, 32 sprites with the 4-per-line limit,
  5th sprite and collision flags. The frame interrupt is the Z80 NMI, as on the real console.
- The emulator draws each line straight into a `picodvi.Framebuffer`. No displayio refresh.
- Sound (3 tones + noise) goes into a looping `audiocore.RawSample` on the TLV320 DAC.
- All buffers are Python-owned. The native code allocates nothing.

## Known issues

- Without `coleco.rom`, commercial cartridges will not run (they hang or show garbage).
- VDP register changes in the middle of a scanline show one line late.
- No Super Game Module, no Roller Controller or steering wheel, no Expansion Module #1.
- Only controller 1 is mapped; controller 2 reads as idle.
