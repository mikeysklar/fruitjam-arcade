# CircuitPython Atari 2600

Atari 2600 games on an Adafruit Fruit Jam, running under stock CircuitPython. The emulator
(6507 CPU, TIA, RIOT) was written for this project and is compiled into a native `.mpy` module.

Not yet tested on hardware. See [NOTES.md](NOTES.md) for what has been verified.

## What you need

| part | notes |
|---|---|
| Adafruit Fruit Jam | RP2350 |
| CircuitPython 11.0.0-alpha | the `.mpy` is built for this version |
| HDMI monitor | 160x240 game area, shown 2x wide |
| headphones or speaker | optional |
| USB gamepad | optional, the 3 onboard buttons work too |
| a `.a26` or `.bin` ROM | not included |

## Setup

Back up your `CIRCUITPY` drive first. `code.py` will be replaced.

```sh
git clone https://github.com/mikeysklar/fruitjam-arcade
cp -r fruitjam-arcade/ports/atari2600/CIRCUITPY/* /Volumes/CIRCUITPY/
cp MyGame.a26 /Volumes/CIRCUITPY/
```

Optional, for sound and gamepad:

```sh
circup install adafruit_fruitjam relic_usb_host_gamepad
```

The board resets and the game boots.

- The first `.a26` or `.bin` file found on the SD card (`/sd`), then on `CIRCUITPY`, is loaded.
  Keep other `.bin` files off the drive.
- The serial console prints the bankswitch scheme it picked, and fps every 5 seconds.
- Most games wait for Game Reset before they start.

## Controls

| Fruit Jam | Atari 2600 |
|---|---|
| Button 1 | Left |
| Button 2 | Right |
| Button 3 | Fire |
| Button 1 + 2 | Game Reset |
| Button 2 + 3 | Up |
| Button 1 + 3 | Down |
| Button 1 + 2 + 3 | Game Select |

| USB gamepad | Atari 2600 |
|---|---|
| D-pad or left stick | Joystick |
| A, B, X, Y | Fire |
| Start | Game Reset |
| Select | Game Select |
| L1 | Toggle left difficulty (A/B) |
| R1 | Toggle right difficulty (A/B) |
| L2, R2 or Home | Toggle Color / B&W |

Power-on switch positions are set at the top of `code.py`
(`LEFT_DIFFICULTY_A`, `RIGHT_DIFFICULTY_A`, `BLACK_AND_WHITE`). Difficulties default to B.

## Cartridges

| size | schemes |
|---|---|
| 2K, 4K | plain |
| 8K | F8, E0 (Parker Bros), FE (Activision), 3F (Tigervision) |
| 16K | F6, 3F |
| 32K | F4, 3F |
| larger, multiple of 2K | 3F |

F8, F6 and F4 with Superchip RAM (SC) are detected. E0, FE and 3F are picked by byte patterns
in the ROM. DPC (Pitfall II), DPC+/CDF (ARM Harmony carts), E7, and paddles are not supported.

## Build the `.mpy` yourself

Same toolchain as the Game Boy build in the root README:

```sh
cd fruitjam-arcade/ports/atari2600/src
make MPY_DIR=../../../../circuitpython ARCH=armv7emsp
cp atari2600.mpy ../CIRCUITPY/lib/
```

Host tests (system `cc`, downloads Klaus Dormann's 6502 test on first run):

```sh
make test
```

## How it works

- `src/cpu6502.h` is the 6507 as a code fragment: every bus access is one cycle, so TIA
  writes land on the right color clock.
- `src/atari2600.c` has the TIA, RIOT, cartridge bankswitching and the module glue.
  The TIA draws lazily: before each TIA access it renders every color clock since the last one,
  straight into the `picodvi.Framebuffer` row, 2x wide. No displayio refresh.
- A frame ends when the game turns VSYNC on. Screen row 0 is scanline 12 after VSYNC
  (`TOP` in `code.py`), 240 lines are shown.
- Sound: both TIA channels are clocked twice per scanline (31.4 kHz), mixed to mono and
  resampled to 22050 Hz into a looping `audiocore.RawSample` on the TLV320 DAC.
  Frames are paced by the samples made, so a game runs at its own frame rate.
- All buffers are Python-owned. The native code allocates nothing.

## Known issues

- Speed on the board is not measured yet. See NOTES.md for the estimate.
- The TIA is scanline-accurate with per-write timing, not a full per-clock model. Tricks that
  depend on sub-cycle effects (HMOVE mid-line "starfield" effects, RESP during HMOVE,
  late HMxx changes) can show wrong positions.
- The NTSC palette is computed, not measured. PAL games run at PAL speed but show NTSC colors,
  and the bottom may be cut off (raise `TOP`).
- Paddles, keypads and the second joystick are not emulated.
